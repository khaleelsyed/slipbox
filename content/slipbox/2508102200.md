When a pointer is returned, the object [escapes](references/2508102143) to the [heap](slipbox/2502142225) as an alternative to returning it's value.

The general advice is that if a method is modifying a struct, it's better for it to be defined on pointers, this is because when a method uses a value receiver, it copies all the fields of the struct onto the method. This is why it's suggested to use pointers for large types.

Although it may seem easier to use pointers as it doesn't involve copying the entire object onto the stack, it can lead to longer and frequent triggering of garbage collection cycles.

Returning more objects as pointers will lead to the [heap filling up](slipbox/2502150011), which will trigger a garbage collection cycle.

Although using the pointer reference for the same object multiple times will not occupy the heap more (as the heap recognises it as 1 object) - this will result in a denser pointer graph. The more references there are to track (even if an object reference is being used multiple times), the garbage collector will need to track all these references during a cycle.
